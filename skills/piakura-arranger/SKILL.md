# Piano arranger

Use piakura's Go tools and the upstream SakuraMML compiler. The editable score is SakuraMML in the [readable](../piakura-readable-mml/SKILL.md) form, one bar per line on the musical clock; musical decisions belong to you. Arrange the whole ensemble into two-hand piano, considering melody, bass, harmony and characteristic accompaniment.

Carry the song's melody, characteristic figures, bass movement and harmonic rhythm into two hands. Start from supported source material; shape its releases and resonance for piano, and reduce notes only where the requested difficulty or keyboard requires it. Preserve listener-accepted phrases when revising an existing arrangement. Declare local melody changes, including articulation, using [rhythm and articulation](references/rhythm-and-articulation.md); the resulting contract verifies the edit, not its musical success.

For fragmented sung phrases, disputed register or a proposed melodic replacement, read [vocal-to-piano adaptation](references/vocal-to-piano.md). Let the source passage determine its groove and harmonic character.

Work inside a piakura job: start from [piakura](../piakura/SKILL.md) if there is none. It records the user's consent and settings (levels, keys, piano mode and the other settings below), `$WORK` for copyrighted input and working scores/reports, and `$DELIVERY` for the finished copies. Script paths below are relative to this skill's directory; run them through that absolute directory. `scripts/tool.sh TOOL …` runs an installed tool such as `smf2sakura` or `midistat`. Inside a Git repository, keep `$WORK` and `$DELIVERY` out of commits. Write the prose people read (score comments, reports, reasons) in the job's [language](../piakura/references/language.md).

For audio or noisy automatic-transcription MIDI, first use [piakura-transcription](../piakura-transcription/SKILL.md) to reconstruct the musical reference. If a `handoff.json` is supplied, run `bash ../piakura-transcription/scripts/transcribe.sh verify-handoff path/to/handoff.json`, read its evidence and uncertainty, and use its `reference_midi` and `melody_channels` below. Paths in that manifest are relative to the manifest directory. Use this curated melody as musical evidence and derive the readable reference from it in step 1, then apply the requested retention objective. Keep unresolved transcription limitations in the arrangement report. A changed handoff artifact must be revalidated before arranging.

1. Run `bash scripts/prepare.sh input.mid "$WORK"`. This emits editable `original.mml`, a canonical backup, analysis JSON and both compiled round-trips. **Both mididiff checks must pass before arranging.** Diagnose a failed conversion rather than editing away its evidence. Then run `bash scripts/readable-reference.sh reference.mid "$WORK/readable"` with the clock options from [piakura-readable-mml](../piakura-readable-mml/SKILL.md) step 1 (`--clock score` for a musical tempo map, `--clock grid …` for a transcription handoff) and account for its report as that skill's step 3. `reference.readable.mid` is the quantized melody contract the levels are written against; the reference itself stays the musical evidence.
2. Read `song.json` and the relevant MML parts. Use the Go analysis sidecars for source and compiled MIDI note/event data; SMF interpretation belongs to the supplied tools. Identify source melody channels, bass, pitched accompaniment, percussion banks and observed section boundaries. Mark uncertain structural labels as provisional. Existing piano is one source voice; consider the other voices too.
3. Before choosing register, texture and expression, read [phrase design](references/phrase-design.md). Mark structural holds and identity-bearing ornaments in the musical contract before simplifying any level. For an authorized external reference, also read [reference comparison](references/reference-comparison.md). Resolve settings: `piano-mode=solo|split` (solo), `keys=N` (88), `lowest-note=auto|MIDI number` (21 for 88 keys, auto for smaller keyboards), `range-mode=fixed|switch` (fixed), `key-policy=preserve|auto-transpose` (preserve). For a constrained keyboard, octave switching or transposition, read [keyboard arrangement](references/keyboard-arrangement.md), read [voicing](references/voicing.md), choose the range jointly with the phrase and accompaniment voicings, and record a validation plan. Read [references/arrangement.md](references/arrangement.md) for musical priorities and the [difficulty model](references/difficulty-model.md) for limits and metric definitions. Select the essential melody channel(s) explicitly after distinguishing instrumental hooks from replaceable fills using [gestures](references/gestures.md). Document role transfers, deletions and difficulty choices in the score comments and a private arrangement report.
4. Create `easy.mml`, `medium.mml`, `hard.mml` in the readable form on the readable reference's clock: copy its `TimeBase` and `TR(0)` lines, keep its bar numbers and its `/** @key */` and `/** @section */` comments, write one bar per line ending in its bar number with its [chord comment](../piakura-readable-mml/SKILL.md#chord-comments) at the start (`/** @chord B:min7 roman=VIm7 */ … // 12`), and put a hand's inner voices in `Sub{}`, keeping each continuing line in the same place from line to line ([voices](../piakura-readable-mml/SKILL.md#voices)). Use the `TR(0)` conductor, `TR(1) CH(1) Voice(1,0,0) TrackName("Right hand")` RH and `TR(2) CH(1) Voice(1,0,0) TrackName("Left hand")` LH. Default `piano-mode=solo` shares CH1 while tracks identify the hands. For `piano-mode=split`, use CH2 for LH and pass `--piano-mode split` to validation. Shared-channel controls are global; release a shared pitch at least one tick before the other hand plays it. Use note values, rests, chords, `{}` triplets and `&` ties as [piakura-readable-mml](../piakura-readable-mml/SKILL.md) describes; keep an exact `%tick` or `Time()` only for a restored deviation, with a comment, and write releases as gates rather than shorter lengths and rests ([written values](../piakura-readable-mml/SKILL.md#written-values)). The melody keeps its key-down lengths only under the readable reference's `q` for its part: write the melody's hand with that `q`, and give accompaniment in the same hand its own lengths or `,P` gates. Preserve tempo/time signatures. Use deterministic expressions. Add `@hand`, `@role`, `@source-channel` and `@section` comments at the relevant passages. Preserve the selected retention contract, including its declared key-down durations and dynamics. Keep the LH below the RH throughout overlapping held intervals by default; intentional role crossings need a specific musical reason. Preserve original deliberate dissonance, and revoice semitones introduced by register compression. For hesitant repetitions, tuplets, gate edits or user-authorized melody reduction, follow [rhythm and articulation](references/rhythm-and-articulation.md) and its explicit retention contract. For Easy, simplify accompaniment first and review whether the retained lead itself meets the requested difficulty; retain phrase identity and harmonic quality.
5. For each level, run `bash scripts/compile.sh score.mml score.mid`, then `bash scripts/validate.sh score.mid level report.json "$WORK/readable/reference.readable.mid" melody_channels`; a reference on another clock gets a warning and mismatches. Append `--keys N --lowest-note MIDI` for fixed range validation or `--arrangement-plan plan.json` for declared register shifts, transposition and inserted rests. After compilation, use a `smf2sakura --no-split-channels --report` sidecar to obtain actual output note IDs for melody mapping. Default hand assignment is `RH=1,LH=2`; pass a final argument to override if compiled tracks differ. With a reference, this helper requires `--preserve-melody`: all selected pitches/onsets/durations, adjusted by the plan if supplied. It requires PASS, including complete hands and `--check-voicing`. Examine every `voicing.issues` pair, including later melody attacks inside held chords. Resolve new clashes by revising the accompaniment or phrase register; use a score-bound `--voicing-review score-review.json` only for musically justified exceptions under [the review contract](references/voicing-contract.md). For an authorized piano adaptation, use the separately audited level-specific contract as reference and retain the original-reference comparison as well. Report the preservation scope alongside physical constraints, and the readable reference's deviations from the original reference (its report and your decisions).
6. Correct hard violations and recompile/revalidate every changed score, refreshing compiled note IDs and any review hashes. Retain a section-by-section musical audit of bass/inversion, harmonic colors, characteristic figures, releases and exception reasons; a PASS or deleting chords alone cannot establish musical completion. Complete the phrase-design review using compiled notes and matched excerpts: register transitions, bass/harmony, inner voices, dynamics, resonance and the ending. Give musical flags a local disposition and distinguish score review from listening acceptance. Review chord quality, phrase continuity and note releases against the source, alongside density and span/leap warnings. If a hard violation or unknown assignment cannot be resolved while preserving the requested music, retain the failing report and state the unresolved passage and tradeoff; do not label it PASS. Deliver the editable MML, compiled MIDI and reports for all requested levels with limitations relevant to playing.
   When a human reviewer takes part, publish the levels beside their reference with [piakura-review](../piakura-review/SKILL.md) and answer its feedback, revalidating every changed score, before packaging.
7. Package the validated scores with `bash scripts/export.sh --language CODE "$WORK" "$DELIVERY"`, CODE being the job's language. Read [distribution contract](references/distribution.md) for the layout. Write customer-facing `arrangement-report.md` with relative links matching that layout; keep working history in `$WORK`. Deliver links to the distribution README and MIDI files.

`scripts/compare.sh reference.mid arranged.mid level melody_channels` prints preservation and playability together. A deliberately edited arrangement is not expected to pass `mididiff` against the original; use that comparator to validate conversion only.
